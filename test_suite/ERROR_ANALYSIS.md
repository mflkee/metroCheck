1. Протокол ещё не загружен в публичную часть АРШИН.

3. В АРШИН хранится другая поверка того же прибора.

## Рекомендации по ручной проверке

1. Открыть PDF по пути.
2. Найти дату поверки и дату "действительна до".
3. Сравнить с АРШИН:
   - дата поверки должна совпадать с `verification_date`;
   - дата "действительна до" — это `valid_date`, отдельная дата (не сравнивается с датой поверки).
4. Если дата поверки в PDF не совпадает с `verification_date` — это ошибка (red) либо другая поверка.
5. Если даты не совпадают вообще — либо другая поверка, либо протокол ещё не в АРШИН.

## Следующий шаг для production

1. В Excel-отчёте программы разделить статусы:
   - **green** — всё ОК (дата поверки совпала с `verification_date`);
   - **red** — требует внимания (дата не совпала или остальные ошибки);
   - **no_protocol** — есть в АРШИН, нет файла;
   - **not_in_arshin** — файл есть, нет в публичном АРШИН.
2. Для red-кейсов проверить вручную 3–5 штук.
3. Если протоколы корректны, но не в public API — подключить API личного кабинета с токеном.
