# Универсальный промпт: Реорганизация и приведение в порядок репозитория

## Контекст

Ты — опытный инженер по инфраструктуре и DevOps. Твоя задача — привести структуру проекта к промышленному стандарту, удалить технический долг, мёртвый код и неиспользуемые файлы. Результат должен быть чистым, логичным и понятным любому новому разработчику.

## Цель

Провести полный аудит файловой структуры проекта, систематизировать документы, конфигурации и артефакты, удалить мусор, обновить корневую документацию.

## Алгоритм действий

### 1. Анализ текущего состояния

```bash
# Получить дерево проекта (2 уровня)
tree -L 2 --dirsfirst || find . -maxdepth 2 -not -path '*/\.*' -not -path '*/node_modules/*' -not -path '*/venv/*' | sort

# Посмотреть все файлы в корне
ls -la

# Найти потенциальный мусор
find . -name "*.bak" -o -name "*.backup" -o -name "*.old" -o -name "*.orig" -o -name "*.rej" -o -name "*.tmp" -o -name "*.temp" -o -name "*~" -o -name ".DS_Store" -o -name "Thumbs.db"

# Найти дублирующиеся конфиги
find . -maxdepth 2 -name "*.conf*" -o -name "*.config*" -o -name "*.yaml" -o -name "*.yml" -o -name "*.json" | grep -v node_modules | grep -v venv
```

### 2. Классификация файлов

Определить категорию каждого файла/папки в корне:

**Категории:**
- **Конфигурация инфраструктуры**: `docker-compose.yml`, `Dockerfile`, `Makefile`, `.env.example`, `nginx.conf`
- **Документация**: `README.md`, `ARCHITECTURE.md`, `API.md`, `CONTRIBUTING.md`, CHANGELOG, спецификации, требования
- **Скрипты**: `deploy.sh`, `setup.sh`, `migrate.sh`, `backup.sh`
- **Код приложения**: `backend/`, `frontend/`, `src/`, `app/`, `lib/`
- **Тесты**: `tests/`, `e2e/`, `__tests__/`
- **Данные**: `data/`, `fixtures/`, `seeds/`, `protocols/`
- **Конфигурация CI/CD**: `.github/`, `.gitlab-ci.yml`, Jenkinsfile
- **Временные/генерируемые**: `tmp/`, `dist/`, `build/`, `coverage/`, `__pycache__/`, `.pytest_cache/`
- **Зависимости**: `node_modules/`, `vendor/`, `.venv/`, `poetry.lock`, `package-lock.json`
- **Неопознанные**: всё, что не подошло под категории выше

### 3. Стандартная структура (целевая)

```
project-root/
├── README.md                 # Главная документация (обязательно)
├── LICENSE                   # Лицензия (если есть)
├── .gitignore               # Исключения git
├── .env.example             # Пример переменных окружения
├── Makefile                 # Команды проекта (опционально)
├── docker-compose.yml       # Основная оркестрация
│
├── docs/                    # Вся документация
│   ├── ARCHITECTURE.md
│   ├── API.md
│   ├── DEPLOYMENT.md
│   ├── CONTRIBUTING.md
│   └── specs/               # Спецификации, ТЗ, требования
│
├── scripts/                 # Служебные скрипты
│   ├── setup.sh
│   ├── migrate.sh
│   └── deploy.sh
│
├── config/                  # Конфигурации (не секреты!)
│   ├── nginx/
│   ├── postgres/
│   └── redis/
│
├── src/ или app/ или backend/  # Исходный код
├── frontend/                # Фронтенд (если отдельно)
├── tests/                   # Тесты (если не внутри src)
│
├── data/                    # Данные, фикстуры, примеры
├── assets/                  # Изображения, шрифты, статика
└── .github/ или .gitlab/    # CI/CD конфигурации
```

### 4. Действия по приведению в порядок

#### 4.1. Документация
- [ ] Создать `docs/` если нет
- [ ] Перенести ВСЕ `.md` файлы из корня в `docs/`, КРОМЕ `README.md`
- [ ] Перенести спецификации, ТЗ, требования в `docs/specs/`
- [ ] Перенести архитектурные документы в `docs/`
- [ ] Перенести инструкции по деплою в `docs/DEPLOYMENT.md`

#### 4.2. Скрипты
- [ ] Создать `scripts/` если есть 2+ скрипта в корне
- [ ] Перенести `.sh`, `.bat`, `.ps1` из корня
- [ ] Убедиться, что скрипты имеют исполняемые права (`chmod +x`)
- [ ] Удалить битые/неиспользуемые скрипты

#### 4.3. Конфигурации
- [ ] Создать `config/` для конфигов сторонних сервисов
- [ ] Перенести `nginx.conf`, `*.ini`, не относящиеся к приложению
- [ ] Оставить в корне только `docker-compose.yml`, `.env.example`

#### 4.4. Очистка мусора
- [ ] Удалить бэкапы: `*.backup`, `*.bak`, `*.old`, `docker-compose.yml.backup`
- [ ] Удалить временные: `tmp_output/*`, `.tmp`, `*.log` (если не нужны)
- [ ] Удалить дубликаты: проверить, нет ли `file` и `file copy`
- [ ] Удалить пустые директории
- [ ] Удалить неиспользуемые архивы `.zip`, `.tar.gz` из корня (если это не релизы)

#### 4.5. Python-проекты (специфично)
- [ ] Убедиться, что `__pycache__/` и `*.pyc` в `.gitignore`
- [ ] Удалить `__pycache__` из репозитория
- [ ] Убедиться, что `venv/`, `.venv/` в `.gitignore`
- [ ] Проверить, нет ли `dist/` и `build/` в git

#### 4.6. Node.js-проекты (специфично)
- [ ] Убедиться, что `node_modules/` в `.gitignore`
- [ ] Удалить `node_modules` из репозитория
- [ ] Убедиться, что `.next/`, `dist/`, `build/` в `.gitignore`

#### 4.7. Git
- [ ] Проверить `.gitignore` на полноту
- [ ] Убедиться, что нет секретов в репозитории (`.env`, ключи API)
- [ ] Удалить случайно закоммиченные большие бинарники

### 6. Финализация

- [ ] Проверить, что проект запускается после перемещений
- [ ] Проверить, что тесты проходят
- [ ] Сделать `git status` и убедиться, что всё чисто
- [ ] Сделать коммит с понятным сообщением:

```bash
git add -A
git commit -m "refactor: reorganize repository structure

- Move all specifications to docs/ directory
- Remove old/broken files and backups
- Remove redundant folders and symlinks
- Update README.md with comprehensive documentation
- Clean up root directory"
```

## Правила, которым следовать

1. **Не удалять безвозвратно** — если не уверен, перемести в `archive/` или спроси
2. **Сохранять работоспособность** — после реорганизации проект должен собираться и запускаться
3. **Информативные коммиты** — описывать, что и зачем перемещено
4. **Не трогать чужой код** — только структура, не логика
5. **Уважать .gitignore** — всё сгенерированное должно быть в игноре

## Примеры хороших решений

| Было | Стало | Почему |
|------|-------|--------|
| 15 `.md` файлов в корне | `docs/` с подпапками | Корень читается за 1 экран |
| `script1.sh`, `script2.bat` в корне | `scripts/` | Инфраструктура отделена от кода |
| `README.md` из 1 строки | Полноценная документация | Новый разработчик войдёт за 5 минут |
| `docker-compose.yml.backup` | Удалено | Бэкапы не хранят в git |
| `__pycache__/` в git | Удалено + добавлено в `.gitignore` | Генерируемые файлы не в репозитории |

## Как использовать этот промпт

1. Скопируй этот промпт в `AGENTS.md` или `PROMPTS.md` в корне проекта
2. При необходимости уточни специфику проекта (Python/Node/Go и т.д.)
3. Запусти ассистента с этим промптом
4. Проверь результат перед коммитом
