# Требования к фотографиям протоколов поверки

## Минимальные границы качества

### 1. Разрешение (DPI)

| Категория | DPI | Качество OCR | Рекомендация |
|-----------|-----|-------------|--------------|
| Отличное | ≥ 300 | 95-99% | Идеально |
| Хорошее | 200-299 | 90-95% | Допустимо |
| Минимальное | 150-199 | 80-90% | Нижняя граница |
| Недостаточное | < 150 | < 70% | Не принимается |

**Проверка**: DPI определяется из EXIF метаданных (поля XResolution/YResolution) или из встроенного заголовка изображения.

### 2. Размер изображения (пиксели)

| Параметр | Минимум | Максимум | Рекомендуемое |
|----------|---------|----------|---------------|
| Ширина | 800 px | 8000 px | 2000-4000 px |
| Высота | 800 px | 8000 px | 3000-6000 px |

Слишком маленькие изображения (< 800px) не содержат достаточно деталей для OCR.
Слишком большие (> 8000px) могут вызывать таймауты при обработке.

### 3. Ориентация

Изображение должно быть повёрнуто так, чтобы текст читался горизонтально (слева направо).

Система автоматически определяет ориентацию через Tesseract OSD (Orientation and Script Detection) и поворачивает изображение на 90°, 180° или 270° при необходимости.

### 4. Освещение и контрастность

| Параметр | Требование |
|----------|-----------|
| Освещение | Равномерное, без бликов и теней |
| Контрастность | Чёткий чёрный текст на белом/светлом фоне |
| Размытие | Отсутствует (текст чёткий по всей площади) |

Система применяет:
- Автоконтраст (PIL `ImageOps.autocontrast`)
- Фильтр резкости (PIL `ImageFilter.SHARPEN`)
- Преобразование в оттенки серого

### 5. Формат файла

| Формат | Поддержка | Примечание |
|--------|----------|-----------|
| PDF | ✅ | Основной формат. Приоритет: текстовый слой → OCR страниц |
| JPEG/JPG | ✅ | Рекомендуется для фото |
| PNG | ✅ | Допустимо |
| TIFF | ⚠️ | Через расширение, без magic bytes проверки |
| BMP | ⚠️ | Через расширение, без magic bytes проверки |

**Важно**: Проверка типа файла осуществляется по **magic bytes** (сигнатуре первых байт), а не только по расширению. Файлы с расширением .pdf, содержащие JPEG внутри, будут корректно обработаны.

### 6. Содержание

Фотография должна содержать полный текст протокола поверки, включая:

- Номер протокола
- Наименование и тип СИ
- Заводской (серийный) номер
- Номер в госреестре
- Год выпуска
- Владелец СИ
- Дата поверки
- ФИО поверителя
- Условия поверки (температура, влажность, давление)
- Результат поверки (пригодно/непригодно)
- Методика поверки
- Диапазон измерений

### 7. Примеры

#### Хорошее качество (рекомендуется)
- Разрешение: 300 DPI
- Размер: 2480 x 3508 пикселей (A4 при 300 DPI)
- Ориентация: 0°
- Освещение: равномерное, без теней
- Контраст: высокий, чёрный текст на белом фоне

#### Минимально допустимое
- Разрешение: 150 DPI
- Размер: 1240 x 1754 пикселей (A4 при 150 DPI)
- Ориентация: ±90° (автоматически корректируется)
- Освещение: допустимы незначительные тени по краям
- Контраст: средний, текст читаемый

#### Неприемлемое
- Разрешение: < 150 DPI
- Размер: < 800px по любой стороне
- Сильные блики, закрывающие текст
- Размытый текст (невозможно прочитать глазами)
- Обрезанный документ (отсутствуют ключевые поля)

## Обработка в metroCheck

### Pipeline обработки изображений

```
Загрузка файла
  ↓
detect_file_type() — определение типа по magic bytes
  ↓
estimate_image_quality() — оценка DPI/разрешения
  ↓
_check_rotation() — авто-поворот через Tesseract OSD
  ↓
preprocess_image() — grayscale + autocontrast + sharpen
  ↓
pytesseract.image_to_string() — OCR (rus+eng)
  ↓
Если confidence < 0.35:
  extract_from_image() — Vision LLM (GPT-4o/Claude/Gemini)
```

### Vision LLM Fallback

Для изображений с низким качеством OCR (< 35% confidence) система автоматически отправляет изображение в vision-модель:

- Бесплатные: `meta-llama/llama-3.2-11b-vision-instruct:free`, `google/gemini-2.0-flash-001`
- Платные: `openai/gpt-4o-mini`, `openai/gpt-4o`, `anthropic/claude-3-haiku`

В подсказку включается предварительный результат OCR для повышения точности.
