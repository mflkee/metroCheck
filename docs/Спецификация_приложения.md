# Спецификация приложения: Система контроля протоколов поверки МКАИР

## 1. Назначение системы

Автоматизированная система проверки наличия и содержания протоколов поверки, оформленных по результатам выполненных поверок метрологической лабораторией ООО «МКАИР». Система замещает ручной труд исполнительного директора (Зонов В.М.) по ежемесячному контролю качества протоколов.

## 2. Архитектура (MCP-based + сетевая)

### 2.1 Топология сети

**Поток данных:**

```
n8n (VPN-сеть МКАИР)                 FastAPI (внешний интернет)
─────────────────────────            ────────────────────────────
1. SMB → читает PDF                  5. POST /checks/run →
2. pdfplumber → текст                   CheckService сверяет
3. POST /protocols/scan →                АРШИН ↔ Протоколы
4. AI extraction:                       6. OpenRouter:
   POST /ai/extract (через               GET https://openrouter.ai

```

**Почему так, а не иначе:**

| Компонент | Где должен быть | Почему |
|-----------|----------------|--------|
| n8n | В VPN (сеть МКАИР) | Читает SMB-шары, в будущем — прямой доступ к БД МКАИР |
| FastAPI | Вне VPN (интернет) | Ходит в OpenRouter (блокируется из РФ), fgis.gost.ru (публичный) |
| Kimi K2.6 | Вне VPN | OpenRouter API, требует внешнего интернета |

| Аспект | Классика | MCP-подход |

### 3.3 n8n (через MCP, внутри AWG VPN)

n8n запускается в Docker с подключённым AWG (AmneziaWireGuard) VPN-туннелем для доступа к сети МКАИР. Воркфлоу построены Kimi K2.6 через MCP.

**Сетевой доступ n8n:**
- ✅ SMB/CIFS — читает PDF протоколы с файловой шары МКАИР
- ✅ FastAPI (через docker bridge network) — API-вызовы
- ❌ OpenRouter — НЕ доступен напрямую (внешний интернет через VPN нестабилен)
- ❌ fgis.gost.ru — НЕ доступен напрямую (если VPN роутит весь трафик)

**AI extraction:** n8n НЕ ходит в OpenRouter напрямую. Вместо этого — через FastAPI AI-proxy:
```
n8n → POST http://fastapi:8000/api/v1/ai/extract → FastAPI → OpenRouter → FastAPI → n8n
```

| Workflow | Триггер | Функция |
|----------|---------|---------|
| **Main** | Webhook `POST /webhook/run-check` | Полный цикл проверки месяца |
| **Extract** | Execute Workflow (sub-workflow) | AI extraction NN1→NN2→NN3 |
| **Scheduled** | Cron `0 9 1 * *` | Ежемесячный запуск |
| **Error Recovery** | Webhook `POST /webhook/retry-protocol` | NN3 retry для сложных случаев |
| **Arshin Monitor** | Cron `*/15 * * * *` | Healthcheck АРШИНа |

### 3.4 Нейросети (через OpenRouter + FastAPI AI-proxy)

n8n (в VPN) не может напрямую ходить в OpenRouter. Поэтому в FastAPI добавлен специальный эндпоинт-прокси:

```
POST /api/v1/ai/extract
Body: { "text": "...", "model": "google/gemma-4-31b-it:free", "system_prompt": "..." }
→ FastAPI валидирует запрос
→ шлёт в OpenRouter (HTTP из внешней сети)
→ управляет fallback NN1→NN2→NN3→NN4
→ возвращает { "content": "...", "model": "...", "usage": {...}, "cost": 0 }
```

**Таблица моделей (актуальна на момент проверки):**

|| Модель | Роль | Контекст | Цена | Когда |
||--------|------|----------|------|-------|
|| `google/gemma-4-31b-it:free` | Основной экстрактор (NN1) | 262K | **$0** | Всегда первой |
|| `qwen/qwen3-next-80b-a3b-instruct:free` | Fallback (NN2) | 262K | **$0** | Если NN1 вернул сложный случай |
|| `openai/gpt-oss-120b:free` | Fallback (NN3) | 128K | **$0** | Если NN2 тоже не справилась |
|| `openai/gpt-4o-mini` | Аварийная (NN4) | 128K | $0.15/1M input | Если все бесплатные упали |

**Автоматический fallback при пропаже модели:**
FastAPI при старте запрашивает список доступных free-моделей через `/api/v1/models` OpenRouter. Если NN1 недоступна — автопереключение на NN2 как основную. Email-уведомление админу.

**Логика выбора (вся внутри n8n Workflow 2):**

```
google/gemma-4-31b-it:free (NN1, первая попытка)
  │
  ├── Успех (confidence ≥ 0.3, все крит. поля есть, значения адекватны)
  │     └→ возвращаем результат, cost = $0
  │
  └── Сложный случай (confidence < 0.3 || t°C аномальная || JSON не распарсен)
        └→ qwen/qwen3-next-80b-a3b-instruct:free (NN2)
              │
              ├── Успех → возвращаем результат, cost = $0
              │
              └── Снова ошибка
                    └→ openai/gpt-oss-120b:free (NN3)
                          │
                          ├── Успех → возвращаем результат, cost = $0
                          │
                          └── Всё ещё плохо
                                └→ openai/gpt-4o-mini (NN4), cost ~$0.001
                                      │
                                      ├── Успех → результат
                                      │
                                      └── Снова ошибка → status: "manual_review"
```

**Сложный случай — формальные критерии:**
1. `data === null` — JSON не распарсился
2. `confidence < 0.3` — менее 3 обязательных полей из 8
3. `temperature < -50 || > 60` или `humidity > 100` — аномальные значения
4. `missing.length > 5` — большинство полей пусты

## 5. Сетевая архитектура (ключевой раздел)

### 5.1 Проблема: два мира

| Сеть | Содержит | Не работает |
|------|----------|-------------|
| **Сеть МКАИР (РФ, за VPN)** | SMB-шары, будущая БД протоколов | OpenRouter, OpenAI, Anthropic |
| **Внешний интернет** | OpenRouter, fgis.gost.ru | SMB, доступ к внутренним ресурсам МКАИР |

### 5.2 Решение: n8n в AWG VPN, FastAPI как мост

```
n8n (Docker + AWG VPN)
  │
  ├── SMB ← читает PDF протоколы (внутри VPN)
  │
  ├── FastAPI (через docker bridge, без VPN)
  │     └── /api/v1/ai/extract → OpenRouter (HTTP)
  │     └── /api/v1/arshin/search → fgis.gost.ru (HTTP)
  │     └── /api/v1/checks/run → PostgreSQL (localhost)
  │
  └── (будущее) БД МКАИР напрямую (внутри VPN)
```

### 5.3 AI Proxy endpoint

Единственный способ для n8n (в VPN) обратиться к OpenRouter:

```python
# FastAPI: app/api/v1/routes/ai.py
@router.post("/extract")
async def ai_extract(payload: AIExtractRequest):
    """Прокси: n8n → FastAPI → OpenRouter → FastAPI → n8n
    Управляет fallback-цепочкой: NN1 (gemma-4-31b) → NN2 (qwen3-next) → NN3 (gpt-oss-120b) → NN4 (gpt-4o-mini)
    """
    models = payload.fallback_models or [
        "google/gemma-4-31b-it:free",
        "qwen/qwen3-next-80b-a3b-instruct:free",
        "openai/gpt-oss-120b:free",
        "openai/gpt-4o-mini"
    ]
    
    for model in models:
        response = await openrouter_client.chat_completion(
            model=model,
            messages=[
                {"role": "system", "content": payload.system_prompt},
                {"role": "user", "content": payload.text}
            ],
            response_format={"type": "json_object"}
        )
        
        # Валидация результата
        result = validate_extraction(response)
        if result.is_valid:
            return {
                "content": response.choices[0].message.content,
                "model": model,
                "usage": response.usage,
                "cost": calculate_cost(response.usage, model),
                "attempts": models.index(model) + 1
            }
    
    # Все модели не справились
    return {
        "content": None,
        "model": None,
        "status": "manual_review",
        "cost": 0,
        "attempts": len(models)
    }
```

**Важно:** n8n в Workflow 2 (Extract) использует HTTP Request node, указывая `http://fastapi:8000/api/v1/ai/extract`, а НЕ прямой URL OpenRouter.

**Параметры AI-proxy:**
```json
{
  "model": "google/gemma-4-31b-it:free",
  "fallback_models": [
    "qwen/qwen3-next-80b-a3b-instruct:free",
    "openai/gpt-oss-120b:free",
    "openai/gpt-4o-mini"
  ],
  "system_prompt": "...",
  "text": "...",
  "max_tokens": 1000,
  "temperature": 0.1,
  "response_format": { "type": "json_object" }
}
```

FastAPI AI-proxy сам управляет fallback-цепочкой: пробует NN1, при сложном случае — NN2, NN3, NN4. n8n получает только финальный результат.

### 5.4 Настройка AWG VPN для n8n

```yaml
# docker-compose.yml (фрагмент)
services:
  n8n:
    image: n8nio/n8n:latest
    cap_add:
      - NET_ADMIN              # для VPN
      - SYS_MODULE             # для WireGuard
    volumes:
      - ./awg-config:/etc/awg:ro  # AmneziaWG конфиг
      - n8n_data:/home/node/.n8n
    environment:
      - N8N_MCP_SERVER_ENABLED=true
      - N8N_MCP_SERVER_API_KEY=${N8N_MCP_KEY}
    entrypoint: |
      sh -c "
        awg-quick up /etc/awg/mkair.conf &&  # поднимаем VPN
        n8n start                             # запускаем n8n
      "
    networks:
      - mkair_network
      - backend_network  # bridge для доступа к FastAPI (без VPN)
```

`backend_network` — обычный docker bridge, НЕ через VPN. n8n видит FastAPI по `http://fastapi:8000`, но SMB-шары доступны только через AWG-интерфейс.

### 5.5 Будущее: FastAPI тоже в РФ сети

Когда появится прямой доступ к БД протоколов МКАИР:

```
FastAPI (РФ сеть + внешний интернет)
  │
  ├── network 1 (host / bridge) → OpenRouter, fgis
  │
  └── network 2 (AWG / VPN) → БД МКАИР (PostgreSQL/MSSQL)
```

Реализуется через `network_mode: dual` в Docker или через второй сетевой интерфейс хоста.

### 5.6 OpenRouter (внешний интернет)
- Единый API-ключ, лежит в env FastAPI
- Роутинг: n8n → FastAPI AI-proxy → OpenRouter
- $10 баланса хватает на ~12 000 запросов Gemini Flash или ~70 000 GPT-4o mini

### 5.7 АРШИН (ФГИС Росаккредитации)
- Открытая часть: `GET https://fgis.gost.ru/fundmetrology/eapi/vri`
- ЛК: требуется Bearer token (получается из ЛК МКАИР)
- Публичные карточки: `https://fgis.gost.ru/fundmetrology/cm/results/{vri_id}`
- **Доступ:** FastAPI ходит напрямую из внешней сети (fgis.gost.ru публичный)

### 5.8 Файловая система (сеть МКАИР)
- Путь: `Метрологическая лаборатория\2_Документы внутреннего происхождения\2_19 Протоколы\{Год}\{Месяц}\{Тип}`
- Монтирование сетевой папки через SMB/CIFS
- **Доступ:** только из n8n (в AWG VPN)

## 6. Улучшенное сопоставление: нечёткий поиск + верификация (дополнение к шагам 6-8)

### 6.1 Проблема

AI при распознавании допускает ошибки в цифрах серийных номеров: 4335 → 4336, 1O0 → 100, 8 → 3, O → 0, Z → 2, S → 5 и т.д. Текущий exact match после `_normalize_serial()` не покрывает такие случаи → протокол уходит в warning "No calibration found for serial: X", хотя по факту протокол есть.

### 6.2 Алгоритм

```
Фаза 1: Точное совпадение (как сейчас)
  └─ успех → OK
  └─ не найдено → Фаза 2

Фаза 2: Нечёткий поиск серийных номеров
  │  Поиск всех serial_number из calibrations за месяц
  │  Levenshtein distance / difflib.get_close_matches
  │  Порог similarity ≥ 0.75
  │
  └─ 0 кандидатов → manual_review
  └─ 1+ кандидатов → Фаза 3

Фаза 3: Верификация кандидатов по cross-полям
  │  Для каждого кандидата проверяются:
  │  • device_name / mit_title (fuzzy, порог 0.7)
  │  • verifier (case-insensitive)
  │  • verification_date (в пределах ±3 дня)
  │  • protocol_number из PDF vs result_docnum из АРШИН
  │  • result (suitable/unsuitable)
  │
  ├── ≥ 2 поля совпало → принимаем (status=ok)
  ├── 1 поле совпало  → warning, ручная проверка
  └── 0 полей         → Фаза 4

Фаза 4: Повторный AI-запрос с подсказкой
  │  Отправить тот же текст в модель с дополнением в system prompt:
  │  "Previously extracted serial_number=X, but it may be incorrect.
  │   Closest DB entries: [A, B, C]. Re-examine the original text carefully."
  │
  ├── успех → обновить serial_number, перезапустить матчинг
  └── неудача → manual_review
```

### 6.3 Детальная реализация

#### Фаза 2 — нечёткий поиск (Python, без pg_trgm)

```python
import difflib
import re

def _fuzzy_find_serial(
    target: str,
    candidates: list[str],
    threshold: float = 0.75,
) -> list[tuple[str, float]]:
    """Поиск похожих серийных номеров."""
    target = _normalize_serial(target)
    normalized = {c: _normalize_serial(c) for c in candidates if c}

    # difflib.get_close_matches — built-in, никаких зависимостей
    matches = difflib.get_close_matches(
        target,
        list(normalized.values()),
        n=5,
        cutoff=threshold,
    )

    # Обратное отображение: normalized → оригинал
    result = []
    for norm in matches:
        original = next(c for c, n in normalized.items() if n == norm)
        ratio = difflib.SequenceMatcher(None, target, norm).ratio()
        result.append((original, ratio))

    return sorted(result, key=lambda x: -x[1])
```

**Альтернатива** (если установлен `thefuzz` / `fuzzywuzzy`):

```python
from thefuzz import fuzz

def _fuzzy_find_serial(target, candidates, threshold=75):
    target = _normalize_serial(target)
    scored = []
    for c in candidates:
        norm = _normalize_serial(c)
        ratio = fuzz.ratio(target, norm)  # 0-100
        if ratio >= threshold * 100:
            scored.append((c, ratio / 100.0))
    return sorted(scored, key=lambda x: -x[1])
```

#### Фаза 3 — верификация кандидатов

```python
def _verify_candidate(
    protocol: ProtocolData,
    calibration: Calibration,
) -> dict:
    """Верифицирует кандидата по cross-полям.
    Возвращает { "matched_fields": [...], "confidence": int, "passed": bool }
    """
    matched = []

    # 1. device_name vs mit_title
    if protocol.device_name and calibration.mit_title:
        ratio = difflib.SequenceMatcher(
            None,
            protocol.device_name.lower(),
            calibration.mit_title.lower(),
        ).ratio()
        if ratio >= 0.7:
            matched.append("device_name")

    # 2. verifier
    if protocol.verifier and calibration.verifier:
        if protocol.verifier.strip().lower() == calibration.verifier.strip().lower():
            matched.append("verifier")

    # 3. verification_date (±3 дня)
    if protocol.verification_date and calibration.verification_date:
        delta = abs((protocol.verification_date - calibration.verification_date).days)
        if delta <= 3:
            matched.append("verification_date")

    # 4. protocol_number vs result_docnum
    if protocol.protocol_number and calibration.result_docnum:
        if protocol.protocol_number.strip() == calibration.result_docnum.strip():
            matched.append("protocol_number")

    # 5. result
    if protocol.result and calibration.result:
        if protocol.result.lower() == calibration.result.lower():
            matched.append("result")

    return {
        "matched_fields": matched,
        "confidence": len(matched),
        "passed": len(matched) >= 2,
    }
```

#### Фаза 4 — повторный AI-запрос с подсказкой

```python
async def _retry_with_hints(
    text: str,
    original_serial: str,
    candidates: list[str],
) -> dict | None:
    """Повторный запрос к AI с подсказкой о возможных серийных номерах."""
    hint = (
        f"Previously you extracted serial_number={original_serial}, "
        f"but it may be incorrect. "
        f"The closest numbers in the database are: {candidates}. "
        f"Please carefully re-examine the serial number in the text "
        f"and verify against other fields like device name, verifier, date."
    )
    # Используем gpt-4o-mini для перепроверки
    response = await ai_extract(AIExtractRequest(
        text=text,
        system_prompt=DEFAULT_PROMPT + "\n\n" + hint,
        model="openai/gpt-4o-mini",
        temperature=0.05,
    ))
    if response.status == "success" and response.content:
        return response.content
    return None
```

### 6.5 Логирование

Результаты fuzzy-матча записываются в `check_results.comment`:

| Ситуация | comment |
|----------|---------|
| Точное совпадение | "Protocol found" |
| Fuzzy match + верификация пройдена | "Matched fuzzy: 4336→4335 (verifier+date)" |
| Fuzzy match, но верификация слабая | "Fuzzy candidate: 4336→4335 (only device_name matches, confidence=1/5)" |
| Повторный AI успешен | "Retry AI corrected serial: 4336→4335" |
| Не найдено | "No calibration found for serial: 4336 (no fuzzy candidates)" |

### 6.6 Почему не pg_trgm / полнотекстовый поиск

- PostgreSQL extension `pg_trgm` требует `CREATE EXTENSION pg_trgm` и superuser прав на БД — не всегда доступно
- `thefuzz` / `fuzzywuzzy` — дополнительная зависимость
- `difflib` — стандартная библиотека Python, 0 зависимостей, работает предсказуемо
- Для 100-500 серийных номеров в месяц скорость difflib более чем достаточна

Если в будущем понадобится производительность на 10k+ записей — перейти на `pg_trgm` с GIN index.
