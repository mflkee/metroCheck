# Этапы проектирования MetroCheck

## Этап 1: Инфраструктура и базовый backend

### Задачи
- [x] Развёрнут сервер (mkair-server) с Docker
- [x] PostgreSQL 16 + Redis 7 (Docker)
- [x] FastAPI слой: routes → services → repositories → DB
- [x] CI/CD: GitHub Actions + staging/production контуры
- [x] Netbird mesh VPN для связи с ПК Зонова
- [x] Synology Drive Client для синхронизации протоколов и токенов

### Результат
- Работающий backend на портах 8002 (prod) и 9002 (staging)
- Авто-деплой на push в main
- Доступ к протоколам через Synology Drive

## Этап 2: Пайплайн проверки (8 фаз)

### Задачи
- [x] `public_api` — загрузка поверок из публичного АРШИН
- [x] `protocol_scan` — рекурсивный поиск PDF, SHA256
- [x] `protocol_ocr` — Tesseract OCR с русским языком
- [x] `data_extract` — извлечение полей (regex + AI fallback)
- [x] `partial_check` — сравнение с публичным API
- [x] `wait_token` — ожидание токена через Synology Drive
- [x] `lk_api` — загрузка деталей из ЛК АРШИН
- [x] `full_check` — полная проверка + отчёт

### Ключевые решения
- **Без n8n:** весь пайплайн внутри FastAPI (`JobQueueService`)
- **Regex primary:** OpenRouter бесплатные модели — только fallback из-за rate limit
- **Async job queue:** задачи с приоритетами (manual > auto), пауза/возобновление

### Результат
- Полный цикл проверки месяца за ~10-15 минут (без учёта ожидания токена)
- Excel-отчёт с результатами
- Email-уведомление о завершении

## Этап 3: Извлечение данных (data_extract)

### Задачи
- [x] Регулярные выражения для 13+ полей
- [x] Извлечение диапазона измерений из таблиц (pdfplumber)
- [x] Нормализация единиц измерения
- [x] Обработка склеенных токенов и многострочных названий
- [x] Извлечение серийных номеров с кириллицей и пробелами
- [x] Fallback на filename для serial_number
- [x] OpenRouter AI (kimi-k2.6:free, qwen-qwq-32b:free) как запасной метод
- [x] `NoAiExtractionService` для deterministic-тестов

### Тестирование
- [x] 25 протоколов (5×МПИ-1..5) — 23/25 confidence 1.0
- [x] Excel-отчёт с результатами извлечения
- [x] Контейнерный тест-раннер (`scripts/run_extraction_test.py`)

### Проблемы
- OpenRouter rate limit (429) на бесплатных моделях — AI непригоден для массового использования
- OCR-качество влияет на точность извлечения
- Сложные форматы (Vegabar, Simatic) требуют доработки regex
