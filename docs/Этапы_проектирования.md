# Этапы проектирования веб-сервиса контроля протоколов МКАИР

## Фаза 0: Инфраструктура (1-2 дня)

### Задачи:
- [ ] Развернуть PostgreSQL 16 (Docker)
- [ ] Развернуть FastAPI проект (шаблон из metroLog: routes/services/repositories/integrations)
- [ ] Развернуть n8n v2.18.4+ (Docker) с включённым MCP Server
- [ ] Настроить MCP Server в n8n:
  ```
  N8N_MCP_SERVER_ENABLED=true
  N8N_MCP_SERVER_API_KEY=...
  ```
- [ ] Настроить AWG VPN конфиг для n8n контейнера:
  - Получить .conf от админа сети МКАИР
  - Проверить `AllowedIPs` — только подсети МКАИР (не `0.0.0.0/0`)
  - Смонтировать конфиг в `/etc/awg/mkair.conf`
  - cap_add: `NET_ADMIN`, `SYS_MODULE`
  - entrypoint: `awg-quick up && n8n start`
- [ ] Создать `docker-compose.yml` с 3 сетями:
  - `backend_network` — bridge (FastAPI + PostgreSQL)
  - `mkair_network` — bridge + AWG (n8n)
  - n8n подключён к обеим сетям
- [ ] Настроить OpenRouter API key (закинуть $10)
- [ ] Реализовать AI-proxy эндпоинт в FastAPI: `POST /api/v1/ai/extract` с fallback-цепочкой NN1→NN2→NN3→NN4
- [ ] Реализовать мониторинг доступности free-моделей OpenRouter (`GET /api/v1/models`)
- [ ] Alembic + первая миграция (пользователи, ai_requests)
- [ ] Подключить Kimi K2.6 (OpenRouter) к n8n MCP Server как MCP Client

### Результат:
```
docker-compose up → работает
  postgres:5432            — доступен
  n8n:5678                 — MCP Server активен, AWG VPN поднят
  backend:8000             — healthcheck OK, AI-proxy работает
  Kimi → n8n MCP           — соединение установлено
  n8n → FastAPI (bridge)   — AI запросы через proxy
  n8n → SMB (AWG VPN)      — доступ к файлам МКАИР
```

## Фаза 2: n8n воркфлоу — сборка через MCP (2-3 дня)

### Процесс:
1. Убедиться, что Kimi подключён к n8n MCP Server
2. Дать Kimi спецификацию (`n8n_пайплайн_спецификация.md`) и задачу:

   > "Построй 5 воркфлоу в n8n согласно спецификации. Используй MCP create_workflow. После каждого создания — validate + execute с тестовыми данными. Чини ошибки, если упало. Начни с Workflow 5 (простой), закончи Workflow 1 (сложный)."

3. Kimi построит воркфлоу в таком порядке:
   - Workflow 5: Arshin Monitor (3 ноды) → validate → execute
   - Workflow 4: Error Recovery (6 нод) → validate → execute
| Workflow 2: Extract (8 нод: NN1 gemma-4-31b + fallback NN2 qwen3-next + NN3 gpt-oss-120b + NN4 gpt-4o-mini для сложных) → validate → execute
   - Workflow 3: Scheduled (4 ноды) → validate → execute
   - Workflow 1: Main (17 нод) → validate → execute

### Что проверять:
- Credentials: только `fastApiBackend` + `arshinToken` + `smtp` (OpenRouter не нужен в n8n)
- Sticky Notes с описанием?
- Webhook URL правильный?
- Fallback NN1→NN2→NN3 работает?

### Результат:
- 5 рабочих воркфлоу в n8n
- Валидация пройдена
- Тестовый прогон выполнен

## Ключевые риски

| Риск | Вероятность | Смягчение |
|------|------------|-----------|
| n8n MCP Server генерирует не то, что надо | Средняя | Чинить через update_workflow или руками |
| Kimi не хватает контекста для сложного воркфлоу | Средняя | Разбить задачу — сначала простые, потом Main |
| АРШИН меняет API | Низкая | Адаптерный слой в FastAPI |
| **gpt-oss-20b:free недоступен / rate limit** | Высокая | Fallback-цепочка NN1→NN2→NN3→NN4, мониторинг доступности через `/api/v1/models`, автоуведомление |
| **Бесплатная модель удалена из OpenRouter** | Средняя | Автопереключение на следующую в цепочке, email админу |
| **AWG VPN отвалился — n8n без SMB** | **Высокая** | **Healthcheck VPN в entrypoint, restart=always, уведомление** |
| **AllowedIPs = 0.0.0.0/0 — n8n потерял FastAPI** | **Средняя** | **Чётко документировано: только подсети МКАИР** |
| Сетевые папки МКАИР недоступны | Средняя | Retry + уведомление |
| **AI-proxy (FastAPI) упал — n8n не может звать LLM** | **Средняя** | **Healthcheck + restart FastAPI, n8n retry logic, fallback-модели проверяются при старте** |
